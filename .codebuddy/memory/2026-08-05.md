## 1.1.2 QA 报告批量修复

用户基于昨日的全面 QA 报告，要求修复所有已识别问题。本次修复跨越 13 个源文件 + 9 个语言文件 + README/design-notes（中英）+ gradle.properties 版本号。

### 修复清单

**严重问题（6 项）**：
1. **Zhipu Provider 未注册**（`MCCF.java` 第 222 行）— 致命功能缺陷，从 0.15.0 起跨越多版本未发现。根因：Provider 注册散落在两处（运行时 registerAllProviders 和界面 ClientConfigState.PROVIDER_IDS），没有单一数据源约束。
2. **RequestModelsPayload 长度校验**（`MAX_JSON_LENGTH = 65536`）— 安全漏洞，恶意客户端无需 op 权限即可触发服务端 OOM（Payload 反序列化发生在权限校验之前）。
3. **LanguageReportPayload 长度校验**（`MAX_LANGUAGE_LENGTH = 64`）— 同上。
4. **ConversationRosterPayload 解码端 idCount/nameCount 上限校验**（`[0, MAX_PARTICIPANTS]`）— 旧代码 `new ArrayList<>(Integer.MAX_VALUE)` 预分配 16GB 直接 OOM。
5. **翻译失败玩家无感知** — 三层方案：TranslationService 加原子计数器 + `/mccf status` 展示统计 + `/mccf stats reset` 子命令 + ClientOnlyChatTranslator 失败时 60 秒去重提示玩家。
6. **ClientOnlyChatTranslator Provider 缓存不失效** — 新增 `invalidateProviderCache()`，由 `ClientOnlyTranslationConfig.save()` 文件写入成功后回调触发。
7. **纯客户端模式历史记录 speakerName 显示 "?"** — 新增 `parseSpeakerName()` 从 `<玩家名>` 前缀解析；新增 `translateAndAppend(text, uuid, speakerNameHint)` 重载让 SubtitlePayload 退回路径传 payload.speakerName()。

**中等问题（5 项）**：
- ClientOnlyChatTranslator UUID.fromString 加 try-catch
- RateLimiter 从固定窗口升级为滑动窗口（ArrayDeque 时间戳队列），避免边界 2 倍突刺触发上游 API 限流；RateLimiterTest 同步更新 + 新增滑动窗口边界测试用例
- HotbarSubtitleRenderer 字幕超 5 条时追加 `… 还有 N 条字幕未显示` 灰色提示
- LogExporter 写入失败时用 AtomicBoolean 提前终止，避免磁盘满时百万行日志爆炸
- 首次加入提示从内存 static 改为持久化到 `client-mode.json` 的 `tippedFirstJoin` 字段；9 种语言文案同时加入 ModMenu 入口说明

**评估后跳过**：
- ChatHistoryScreen.toggleFilterPanel 优化 rebuildList — listTop 随面板展开/收起变化，1.21.1 widget 不能动态改位置，必须重建。优化风险大于收益。
- 字幕渲染每帧重建换行列表（M2）— 改动风险高，留作后续优化。
- HearingResolver 射线检测批处理（M4）— README 已标注为已知限制，改动风险高。
